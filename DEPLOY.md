# Деплой на Vercel (с Postgres)

## Что изменилось по сравнению с версией из Grok

- Имя партнёра: Артём → Андрей (`src/lib/store.ts`)
- P2P (WebRTC) убран целиком — он синхронизировался только пока оба
  устройства одновременно онлайн, для вашего сценария это не подходило
- Вместо него — обычный сервер + база:
  - `migrations/0001_app_state.sql` — таблица на одну строку с данными
    приложения (задачи, хотелки, капсулы и т.д. — единым JSON)
  - `src/lib/sync/state.server.ts` — `/api/state`: читает/пишет эту строку
  - `src/routes/api/state.ts` — монтирует эндпоинт
  - `src/lib/sync/client.ts` — опрашивает `/api/state` каждые 8 секунд,
    плюс сразу при возврате в приложение (фокус вкладки/пробуждение
    экрана), плюс шлёт свои изменения с небольшой задержкой (400 мс)
  - `src/components/shell.tsx` — подключает синхронизацию в корне

Всё уже проверено вживую: `npm run typecheck`, `eslint`, `npm run build`
(собирается под Vercel-пресет), плюс я поднимала dev-сервер и руками
прогоняла `/api/state` — включая проверку, что конфликтующая запись с
устаревшей меткой времени корректно отклоняется (409) и не затирает чужие
данные.

## Шаги деплоя — порядок важен

1. **Запушить этот код в GitHub** (обновить существующий репозиторий или
   создать новый — не важно, приватный или публичный)

2. **Подключить Neon Postgres к проекту в Vercel — ДО первого деплоя.**
   Это единственный шаг, где порядок принципиален: если в проекте на
   момент сборки не будет переменной `DATABASE_URL`, код молча откатится
   на временную встроенную заглушку вместо настоящей базы (она не
   рассчитана на serverless и не даёт постоянного хранения) — то есть
   получится тот же класс проблемы, что была с P2P, просто по другой
   причине, и снаружи не будет заметно, что что-то не так.

   Как подключить: Vercel Dashboard → Add New → Project → выбрать
   репозиторий → **до нажатия Deploy** открыть Storage → Marketplace →
   **Neon** → Continue → создать новую базу. Neon сам пропишет переменную
   `DATABASE_URL` в Production и Development — руками копировать не нужно.

   (Если всё же успела задеплоить раньше — не страшно, просто подключи
   Neon тем же способом через Storage → Marketplace уже после, а потом
   сделай Redeploy из вкладки Deployments.)

3. **Deploy.** Таблица создастся сама: в `package.json` команда сборки уже
   включает `db:migrate`, она применяет `migrations/0001_app_state.sql`
   автоматически при каждой сборке.

4. Открыть на двух устройствах. Первое, что откроет приложение, «засеет»
   базу своими локальными данными — второе подтянет их при следующем
   опросе (до 8 секунд, или мгновенно, если открыть уже после того, как
   первое устройство успело записать).

## Как это ведёт себя на практике

- Партнёр не обязан быть онлайн одновременно с тобой — данные лежат в
  базе постоянно, а не только пока установлено P2P-соединение
- Задача, добавленная в 14:00, будет ждать в базе сколько угодно и
  появится у партнёра, как только он откроет приложение — даже если это
  случится на следующий день
- Если оба отредактировали что-то без доступа к сети одновременно —
  победит та версия, что сохранилась на сервер последней (целиком, не по
  отдельным полям); версия, которая пришла раньше и не совпала с текущим
  состоянием на сервере, отклоняется с ошибкой 409 и подтягивает актуальную
  версию вместо того, чтобы её молча затереть
- Тайное голосование и капсулы хранятся в той же общей записи — интерфейс
  скрывает чужой голос до момента, пока не проголосуют оба, но сами данные
  уже лежат в базе на сервере. Это вопрос доверия между вами, а не
  технической гарантии приватности

## Опционально: полноценная авторизация

В проекте уже есть `better-auth`, просто выключен
(`.grok/app-env.json` → `VITE_AUTH_ENABLED: false`). Отдельная задача,
не входит в этот набор правок.

## Про флаг `deploy.database` в `.grok/app-env.json`

Он остался `false` — это метаданные именно для платформы Grok (говорят
её собственному хостингу, провижнить ли базу при деплое через саму
платформу). На деплой через Vercel он никак не влияет — код смотрит
только на переменную окружения `DATABASE_URL`.
